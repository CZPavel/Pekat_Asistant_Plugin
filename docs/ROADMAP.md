# Roadmap and acceptance gaps

The 0.3.0 baseline is delivered: three skills, complete public reference snapshot,
bundled offline tools, narrow optional Core adapter, GitHub marketplace, build/CI,
actual local installation and a new-chat tool smoke. See [validation](VALIDATION.md).

Remaining work is scoped independently; this does not announce a live writer:

- Validate plugin installation and discovery in each intended host with a fresh session.
- Broaden the already passing synthetic offline-tool smoke with representative
  authorized inputs; compare complete application outcomes separately.
- Exercise the optional local Core adapter against a separately installed compatible Core and its real contracts. Its bundled scope is identity, offline capability lookup and deterministic planning; project/live writing is outside that adapter.
- Review current official version- and model-specific documentation and keep historical evidence scoped.
- If the owner requests GPT migration, compare the actual account configuration and test behavior and integrations in the destination.
- Test real PEKAT runtime and physical integration separately when authorized and available; offline analysis is not hardware acceptance.

The complete response-fixture suite, other hosts, arbitrary Core builds and all
physical integrations remain separate acceptance work. No official Plugin
Directory submission or original GPT account action has been performed.
